# M4 Review — Curated Synchronous Core

## Scope

Oracle independence, numerical correctness, binary operands, lifetime safety, depth rules, declarations, and runtime package entry points.

## Confirmed findings

- Binary operations initially ignored their second operand.
- The Node package entry pointed at TypeScript source rather than distributable JavaScript.
- Extraction buffers needed explicit native release.
- Deskew fixtures needed a non-degenerate slant.
- FinalizationRegistry holdings could not be the target object itself.
- Finite parameter validation, poisoned-session checks, and operation-depth coverage needed expansion.
- A dependency configure timestamp caused a one-byte reproducibility difference across dates.

## Fix round

- Binary operations now retain and use the real second operand.
- Generated JavaScript and declarations are emitted under "dist/types/" and exercised by a real consumer.
- Extraction copies and frees native buffers.
- Slanted fixtures exercise actual deskew rotation.
- Finalizer holdings use separate records and remain warning-only.
- Validation and depth-rule matrices cover the public operation union.
- The dependency build string is pinned to its release value, removing wall-clock input.

## Evidence

CI runs 33917740452, 33928265707, and 33934560265 passed. Native oracle, mutation checks, strict consumer compilation, package analysis, and byte reproducibility were green.

## Decision
