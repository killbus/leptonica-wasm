### 二进制体积与性能（perf）

- **判断 1**：裁决方向稳健，8x 是保守**上界**——结构性下界 ≥2×（full-abi 严格包含 default 全功能 + 全解码侧 + ~2700 函数体传递闭包，与 100KB 阈值差一个数量级）；-O2 关 metadce 使 full-abi 偏大。同优化级别复核无需解导出名压缩：加 default@-O2 对照（~6s）即得干净对照。
- **判断 2**：裁剪证据链深度证据强（库级解码符号 0）但不在 CI；CI 内两断言一弱一空——`/\bpixRead\w/` 漏裸名；default 模式 metadce 压缩导出名为 da/ea，`/^pix(Read|Write)/` 导出检查**结构性空转**。
- **判断 3**：静态锚定 105KB 的 M2 体积门禁会在 M4 爆掉（DWA 形态学等体积大户）；须预算阶梯 + M4 冻结后重定基线。105.4KB 已超名义阈值 5%，margin 薄未文档化。
- **判断 4**：M1 不测运行时性能可接受（spike 定位），但 full-abi 逃生舱 -O2 性能未声明、INITIAL_MEMORY 32MB 无 MAXIMUM_MEMORY 与已知泄漏交互（16MP 重复 extract 棘轮至 OOM）应显式进 M2/M4。

### 供应链安全 pin 完整性（supply）

- **判断 1**：pin 链 commit 级寻址层扎实——三个 action pin API 复核全部 verified 且 latest；emsdk 走 git SHA 寻址（比 tarball 强）；`permissions: contents: read` + `persist-credentials: false` 到位；tar 穿越结构+行为两层封死（四 tarball 实测 0 穿越/0 symlink；GNU tar 1.35 硬拒绝 `..`，fail-loud）。
- **判断 2**：实质新缺口在**工具链二进制层**——emsdk install 从 GCS 拉取 298MB wasm-binaries.tar.xz 等全程仅 TLS 无内容哈希校验（读 pin commit emsdk.py 源码证实）；`sdkReleaseHash` 是 revision 寻址非哈希。M2 sha256 白名单只覆盖依赖 tarball、漏了生成最终 wasm 的编译器本身。
- **判断 3**：整条链根信任弱点是**仓库自身**——main 无分支保护（API 实测）、单人仓库、白名单与被校验对象同库存放属自引用信任；分支保护缺位使「谁来看住白名单」无答案。

### 构建工程（build-eng）

- **判断 1**：编排分层健康、幂等骨架正确（fetch 层 `.pin-commit` 内容比对正确失效），但 **`.done` 编译标记不随 pin/flags 失效**——pin 变更后 stale `.done` 跳过编译静默链接旧库。M1 无实害（CI 每次 wipe），M2 缓存复用 `tmp/build` 前必修。
- **判断 2**：确定性证据真实但边界清晰——独立验证产物无路径泄漏（`/home/runner` 等 0 命中）；full-abi d.ts 恰好列出全部 2745 导出与 build-report 交叉验证（且可直接作 M3 raw 层松 d.ts 原型）；但仅 wasm 哈希、同 runner 同进程、`ubuntu-latest` 移动靶。
- **判断 3**：emsdk pin **双写漂移**——yml 硬编码 emsdk commit/版本，注释宣称来源 versions.json，实际 versions.json emsdk 节零消费者。
- **判断 4**：七次迭代知识沉淀质量高（metadce 裁决链闭环为 post-link 重命名预埋路径），足以让 M2 避免重踩。

## 判官总结

**收敛点**（三视角独立得出、相互印证）：

1. **裁决方向稳健是三方共识**：perf 给出结构性下界 ≥2× 量化、supply 确认 pin 链无新违规、build-eng 独立验证产物无路径泄漏。零 blocker，M1 具备过门条件。
2. **CI 断言加固是三视角交叉点**：perf F2（断言一弱一空）与 trellis-check nit-1 同源；supply N3（缓存旁路）与 build-eng W1（.done 失效）都指向「M2 缓存分层必须带内容复验」——两个视角从不同路径撞上同一结论。
3. **M2 供应链防线需扩展**：supply W1（工具链哈希校验）是全场唯一实质性新增缺口；W2/W3（dependabot 加 github-actions ecosystem、分支保护）补全既有清单。

**分歧**：无实质分歧。一处事实矛盾已裁决——build-eng N1 质疑 research 称 `CMAKE_POLICY_VERSION_MINIMUM=3.5` 为「关键」无证据；主会话实测四依赖树全部声明 ≥3.10（zlib 3.12…3.31 / libpng 3.14…4.2 / libjpeg-turbo 3.15…3.28 / leptonica 3.10），无任何 <3.5 声明，journal 七次迭代亦无 cmake policy 失败记录——**build-eng 正确，research 表述已修正**（flag 定性为预置防御，M2 验证移除）。

**留 M2+ 议题**（不阻塞，已回填对应文档）：门禁计费口径（perf）、链内放大守卫归属（perf，M4 设计期）、MAXIMUM_MEMORY 裁决（perf F8）、逃生舱性能口径（perf F7）、`--closure 1` 与 embind 兼容性实测（perf）、跨 runner 复现时间点（supply W3/build-eng W3）、白名单再生成纪律（supply 议题 1）、check-exports 按模式分层比较对象（build-eng 议题 4）、开关名三分裂统一（build-eng 议题 2，`--full-abi` vs `--raw-abi` vs `/full`）。
