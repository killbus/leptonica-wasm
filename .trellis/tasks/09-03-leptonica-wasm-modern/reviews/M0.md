### 发言要点

**Sorhus**：19 行 package.json、0 运行时依赖、ESM-only day-1 落地是正确起点；但包的可发布性缺口必须与首个 src 文件同天补齐（exports/files/sideEffects）。@types/node 漂移从 nit 升 warning——类型必须跟最旧支持引擎而不是最新 Node。warning 5（exports 骨架、@types 降 20、types:["node"] 全局注入应拆域、prepublishOnly 缺失、.gitignore 缺生成物条目）；nit 3（packageManager、README=M6、凭据文件依赖 exclude——已验证生效）。

**Feross**：lockfile 卫生近教科书（92/92 integrity、全 npmjs.org、唯一 install script 良性 fsevents），但仓库零 commit——生命线只存在于磁盘上；exclude 不可版本化，需要第二层防线（committed pre-commit 通用 secret 模式扫描，不点名文件）；third_party 参考克隆无版本锚点；M6 前需 wasm 复现构建 + sha256 清单（npm integrity 证明不了 wasm 与 C 源码的对应关系）。warning 4 + nit 2（CI 默认 --ignore-scripts、TS 7.x 早期版本盯梢）。

**Hejlsberg**：严格性套件已是最终形态九成（noImplicitOverride / noFallthroughCasesInSwitch 已在位，无需加）；实测复现 `lib ES2022 + types node` 组合下 WebAssembly 全局 TS2304 未定义——第一个 TS 文件摸 WebAssembly 就撞墙，config 拆分死线在此之前；d.ts 管线 M0 只欠 exports/types 骨架，root 永远 noEmit。warning 3 + nit 3（erasableSyntaxOnly、noPropertyAccessFromIndexSignature 可缓、M4 补 consumer 视角编译验证）。

## 判官总结

**收敛点**：① @types/node 漂移（双票 nit→warning）② 单域 tsconfig（双票，WebAssembly TS2304 实证）③ exports 骨架原子落地 ④ packageManager pin（全员）⑤ 零 commit（lockfile 信任未入历史）。
