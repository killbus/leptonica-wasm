# M6 Review — End-to-End and Release

## Scope

Browser/Node consistency, package contents, README and license quality, release provenance, and publication-channel policy.

## Confirmed findings

- The tag-only release workflow needed its own structural review because push CI did not execute it.
- Package review had to include the complete full-ABI escape hatch and content manifest.
- Browser tests needed source-safe imports during pre-build type checking.
- Tar listing checks needed to avoid early-pipe termination under "pipefail".
- README code fences required rendered-output verification and a new version to reach a published tarball.

## Disposition

- Release CI performs a cold verified build, pnpm install, tests, package review, and GitHub Release creation.
- Registry publication and registry credentials were removed from the release design.
- Branch protection was enabled before production release.
- Browser and Node paths produce byte-identical PNG output.
- Package review reads the complete archive listing before checking required paths.
- Version 0.1.1 contains the corrected README and is the current release artifact.

## Evidence

- Main CI run 33949334034 passed.
- Release run 33949945440 completed the first GitHub Release path.
- Release run 33950744417 published the corrected 0.1.1 package.

## Decision

Gate passed. GitHub Release is the sole publication channel and pnpm is the sole package workflow.
