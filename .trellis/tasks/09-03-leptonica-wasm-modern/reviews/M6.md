## 2026-09-05 发布渠道裁决（用户指示）

**npm 发包禁用，发布只走 GitHub Release**（用户原话：「禁用 npm 发包，只需发布到 github 就可以了」）。变更：

- release.yml 的 Publish 步骤（pnpm publish --provenance + NPM_TOKEN fail-loud）整体移除，替换为 softprops/action-gh-release（v3.0.3 commit-pin efb3536，研究记录在 workflow 注释）创建 GitHub Release，tarball 作为 release asset 附上
- job permissions 从 contents:read 升为 contents:write（创建 Release 所需）；setup-node 的 registry-url 移除（不再向 npm registry 认证）
- 发布前置从三项减为两项：NPM_TOKEN secret 不再需要，分支保护仍为信任根
- 分发语义：用户从 GitHub Release 下载 tarball，或 npm install <release tarball URL> 直装；sha256 manifest 仍是内容锚（在 tarball 内，dist/sha256.json）
- npm provenance 通道随发包禁用一并移除——GitHub Release 本身携带 run 元数据（workflow run 链接、commit SHA），可追溯性由 release notes 的 generate_release_notes（commit 列表 + diff 链接）承担
- README Provenance 章节同步改写（分发渠道 GitHub Releases，不再提 npm integrity）
- prepublishOnly 保留：npm 发包已禁用所以它是死代码，但如果未来重新启用 npm 分发，这个门（typecheck + test + build）仍然正确，不构成负债

设计 §3「决策 ⑪ npm publish 带 provenance」自此被用户指示覆盖：发布渠道事实标准 = GitHub Release tarball。回滚点不变（删 Release / 删 tag 重推）。
