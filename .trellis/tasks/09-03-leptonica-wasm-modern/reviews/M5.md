## 第二层：双视角并行独立评审

### Armstrong（并发与生命周期）

- **Blocker**：design.md:21/223 与 implement.md M5 均承诺 session.terminate() = worker.terminate() 核弹选项，但 session.ts 只暴露 @internal markTerminated()——用户拿不到扳机，唯一关闭路径 close() 是 FIFO 握手（长 op 悬挂）。「若 v1 不暴露须改 design」→ 判官核实时 implement.md 明列 terminate()，按承诺本门必修
- Warning：worker.ts wireWorker switch 无 default——init 后收到未知消息（含重复 init）静默蒸发，pending 永悬
- Warning：terminate 测试在无 in-flight 时调 markTerminated，「pending promises reject」注释与行为不符，#rejectPending 终止路径零覆盖
- Warning：毒化后失败形状不一致——toPNG 走 rejection，findSkew/countPixels/connComp/histogram/average 在 #assertAlive 同步 throw
- Nit：messageerror 不监听；#post 抛异常时 pending 泄漏（与无超时同病理）
- 复核 F1 修复：isClosed() 守卫方向正确但只修一半——worker 在 farewell 往返期间死亡时 await farewell 仍会 reject，finally 清理路径会被顶替。修法：farewell 失败静默 resolve（close 是指令不是请求）

### Hickey（跨 bundler 兼容）

- **Blocker**：esbuild fixture 产物运行时必然 404 wasm——run.mjs 只 build 不拷 wasm；产物 worker.mjs 保留 new URL("leptonica.wasm", import.meta.url) 原样（esbuild 不重写资产 URL），dist/ 只有 main.mjs + worker.mjs。这正是矩阵要抓的 tesseract.js 式 bug，build-only 恰好放过
- Major：sideEffects glob **/worker.mjs 把 dist/types/worker/worker.mjs（boot 代码）与 dist/worker.mjs（104B shim）混为一谈——碰巧都对（副作用传递性），非设计
- Minor：dist/types/ 装运运行时代码是命名谎言（M4 历史），M6 前机械 rename 成 dist/esm/
- Nit：node.ts resolveEntry() 五层向上探测是布局启发式而非契约（fail loud 缓解）
- 对 W1 裁决建议：第三条路——现在就加布局断言（产物里抽 wasm URL 验证文件存在），esbuild 今天就会红；改措辞是把 done 重定义为已交付的东西
- 对 worker.mjs 双入口：本拟开火，读完 Step 4 约束记录后收回——sibling/vite 内联/Node 扩展名三约束相撞，拷贝是最不坏解

## 判官总结

两个视角独立收敛：**死亡传播链和协议主干是健康的（链接完备、请求表干净、teardown 幂等、双端适配对称），但两处承诺没兑现——一个在 API 面（terminate 扳机焊死在 @internal），一个在验证面（esbuild 那条腿假绿：产物必然 404 wasm，恰是矩阵存在理由的场景）。** 两者还有一个共同根因：build-only 的验证边界恰好停在承诺边界之前。

W1 裁决：采纳 Hickey 第三条路——**现在加布局断言**（不推迟 M6 也不改措辞了事）。理由：wasm URL 在产物里是静态可抽的（new URL 字面量），「worker 要 fetch 的文件存在」不需要浏览器才能验证；断言对 esbuild 立即红 = 证明它抓真 bug，修完（拷 wasm 进产物）转绿 = 矩阵对四工具都有了布局级底线。M6 Playwright 再补浏览器运行时层。
